# 仕様書：ローカル体験予約アプリ（MVP縮小版）

元の仕様書（[01_spec.md](01_spec.md)）をもとに、MVPを「事業者が店舗を登録し、旅行者が一覧から選んでチャット・予約する」範囲に絞った版。
画面は **旅行者画面** と **事業者画面** の2つ。

- 【推測】：元の仕様書で推測とされていた内容
- 【提案】：今回の見直しで細部を補った案。実装前に確認する

---

## 1. ターゲット

### 旅行者（需要側）

- Lee Wei Ming（29歳）。シンガポール在住、IT勤務。初めての訪日で、関西を3泊4日で回る。
- 日本語はできず、英語は使える。中国語（簡体字）も読める【推測】。
- 情報は中華圏SNS、Instagram、Googleマップで集める。やりたいことは抹茶体験と地元の居酒屋。
- 旅程の骨格だけ決め、細部は前日や当日に決める【推測】。eSIMで常時オンライン【推測】。
- 「観光地化されていない本物の体験」を求める一方、失礼や場違いを恐れ、断られるのが怖くて店に入れない【推測】。

### 事業者（供給側）

- 宇治の小規模茶農家をはじめとする、体験・飲食店・ツアーの小規模事業者。
- 60代夫婦と、手伝う30代の子どもの家族経営を想定【推測】。英語はできない。
- PCはほぼ使わず、スマホとメール・LINEは使う【推測】。受け入れは1日1〜2組、各2〜6名【推測】。
- 不安は、言葉、無断キャンセル、文化の違い【推測】。

## 2. 課題

- **旅行者**：検索しても観光バス向けの定番しか出てこない。気になる店を見つけても、英語の情報や予約手段がなく入れない。
- **事業者**：海外から問い合わせが来ても、英語で返せず予約の仕組みもないため、断るしかない。

MVPでは、元の仕様の「発見の断絶」と「受け入れの断絶」の2つを解く。「入店の断絶」は次フェーズに回す。

## 3. 解決策

**MVPのコアバリュー**：日本語しか使えない事業者が自分で店舗を登録でき、旅行者はそれを一覧で見つけて、言葉の壁なしにチャットと予約まで進められる。

| 画面 | 解く課題 | 主な機能 |
| --- | --- | --- |
| 事業者画面 | 受け入れられない | 日本語だけで店舗登録（自動翻訳）、時間枠と上限人数の設定、翻訳チャットへの返信、予約の確認とキャンセル |
| 旅行者画面 | 見つからない・予約できない | 店舗の一覧と絞り込み、詳細ページ（英語・簡体字）、翻訳チャット、即時予約 |

### 元の仕様から変えた点

| 項目 | 元の仕様 | MVP縮小版 |
| --- | --- | --- |
| 予約の確定 | リクエストを送り、事業者が承認 | 事業者が決めた時間枠の上限人数内なら **即時確定**。満席なら予約できない |
| ローカル度 | 事業者が自己申告し、旅行者が絞り込む | 点数や「ローカル度」という項目は持たない。**客層・営業年数・主要駅からの所要時間** を事実として載せ、旅行者が判断する |
| キャラクター | 初回登録の会話、各画面での一言、よくある質問 | **一覧画面で一言話すだけ** |
| 支払い | 承認時に手数料をカード決済 | **カード登録のみ**（請求はしない。無断キャンセルの抑止） |
| 翻訳 | 機械翻訳＋用語集 | **AI翻訳**（英語・簡体字） |
| 通知 | プッシュ＋SMSかメール | **メールのみ** |
| 事業者の登録 | 運営が電話で確認して掲載 | **誰でも登録でき、即公開** |

## 4. 画面フロー

### 4.1 旅行者画面

① **入口**：Google検索・マップ、ホテルのQRコードからWebで開く。アプリのダウンロードは不要。ログインも不要。

② **一覧画面**
- 初回は表示言語（英語／簡体字）と表示通貨を選ぶ。端末の設定から初期値を推定する。
- キャラクターが画面上部で一言あいさつする（固定文、英語・簡体字）。×で閉じられる【提案】。
- 登録された店舗を一覧で表示する。各カードには写真、店名、カテゴリ、エリア、料金（日本円＋自国通貨の目安）、客層、営業年数、主要駅からの所要時間を出す。
- 絞り込み：カテゴリ、エリア、予算、客層、営業年数、主要駅からの所要時間。
- 並び順は新着順【提案】。おすすめ順は次フェーズ。

③ **詳細ページ**（英語・簡体字に自動翻訳）
- 写真、説明文、料金（日本円＋目安）、所要時間、受け入れ人数、支払い方法（現金のみ／カード可）、住所、カテゴリ別項目、キャンセルポリシー。
- 「質問する（チャット）」と「予約する」の2つのボタン。どちらも押した時点でログインを求める。

④ **チャット**
- 旅行者は英語か簡体字で書き、事業者には日本語で届く。事業者の返信は旅行者の言語に翻訳して表示する。
- 原文も「原文を見る」で確認できる【提案】。
- 新着メッセージはメールでも知らせる。

⑤ **予約**
- 日付をカレンダーから選ぶ → 空きのある時間枠を選ぶ → 人数を選ぶ。満席の枠、定休日、受付停止日、受付締切を過ぎた日は選べない。
- 食事制限（選択式）と事業者へのメッセージ（任意）を入力する。メッセージは日本語に翻訳して届ける。
- カードを登録し、その店のキャンセルポリシーに同意して確定する。カードには請求しない。
- 確定画面には、日時、人数、住所、現地で払う金額（日本円＋目安）、キャンセル期限を表示する。確定メールも送る。

⑥ **マイ予約**
- 予約の一覧と、キャンセル期限内のキャンセル。キャンセルすると枠は自動で空く。
- 予約ごとのチャットに進める。

### 4.2 事業者画面（スマホファースト、日本語のみ）

① **アカウント登録**：メールアドレスで登録する。複数の端末から同じアカウントでログインできる。

② **店舗登録**（日本語で入力し、英語と簡体字に自動翻訳）
- 共通項目：店名、カテゴリ（体験／飲食店／ツアー）、エリア、住所、説明文、写真（1〜5枚）、料金、所要時間、支払い方法（現金のみ／カード可）。
- 地元らしさの情報：客層（ほぼ地元の人／半々／観光客が多い）、営業年数（10年未満／10〜30年／30年以上）、主要駅からの所要時間（最寄りの主要駅と分数）。
- カテゴリ別項目：下の「カテゴリ別項目」の表を参照。
- 予約の設定：
  - 時間枠（開始時刻）と、枠ごとの上限人数
  - 定休日（曜日）
  - 受付締切（当日OK／前日まで／2日前まで）
  - キャンセルポリシー（無料キャンセルの期限と、当日キャンセル料の有無）
- 保存すると即公開。「非公開にする」でいつでも止められる。

③ **受付停止日**：カレンダーで日をタップして受付を止める。期間を選んでまとめて止めることもできる。

④ **予約一覧**
- 日付順に、旅行者名、人数、時間枠、食事制限、メッセージ（日本語訳）を表示する。
- 新しい予約が入るとメールで知らせる。
- 理由（臨時休業／天候／その他）を選んで予約をキャンセルできる。旅行者には理由を翻訳してメールで知らせる。
- 来店しなかった予約に「来店なし」を付けられる。運営が当日キャンセル料の請求を判断する材料にする【提案】。

⑤ **チャット**：旅行者ごとのスレッドを日本語で読み書きする。新着はメールで知らせる。

## 5. イレギュラーケース

### ① 空っぽ

- 絞り込みなしで一覧を開く → 全店舗を新着順で表示する。
- 日付・時間枠・人数が未選択 → 確定ボタンを押せない。足りない項目を英語・簡体字で示す。
- 事業者が必須項目を空のまま保存 → 下書きとして保存し、公開はできない。
- 時間枠を1つも登録していない店舗 → 詳細は公開するが、予約ボタンは出さずチャットのみにする【提案】。

### ② 過剰

- 枠の残り人数を超える人数 → 残り人数までしか選べない。
- 長すぎるメッセージ → 文字数の上限を設け、翻訳APIへの過剰な入力を防ぐ。
- 一人の旅行者が大量に予約する → 同時に持てる未来の予約数を制限する【提案】。
- 絞り込みで0件 → 条件を一つ外した場合の件数を示す。

### ③ 悪意

- スクリプトや記号の羅列 → すべての入力をエスケープし、画面や翻訳結果で実行・表示されないようにする。
- 嫌がらせのメッセージ → 事業者がチャット相手をブロックできる【提案】。
- 架空の店舗登録 → MVPは即公開のため防げない。旅行者側に「この店舗を報告」ボタンを置き、運営がDBで非公開にする【提案】。

### ④ 中断

- 予約入力の途中で閉じた → 入力内容を端末に残し、次に開いたときに再開できる。
- カード登録の途中で閉じた → 予約は未確定のまま。枠は押さえない。
- 為替レートの取得に失敗 → 最後に取得したレートと取得日時を表示する。日本円は常に表示する。
- 同じ枠を2人が同時に予約 → 確定時に残り人数を再確認し、後から確定した側には満席と伝える。

### ⑤ 別人

- 日本人や在住外国人が使う → 拒まない。表示言語に日本語も選べるようにする【提案】。
- 団体や旅行会社が大人数で使う → 枠の上限人数で自然に制限される。
- 事業者の家族が複数端末で使う → 同じアカウントで複数端末のログインを認める。

## 付録：MVPの決定事項と詳細

### 決定事項

| 論点 | 決定 |
| --- | --- |
| 画面 | 旅行者画面と事業者画面の2つ（どちらもWeb、スマホファースト） |
| 解く課題 | 発見と予約。入店支援は次フェーズ |
| カテゴリ | 体験、飲食店、ツアー。宿は対象外 |
| 事業者の登録 | 誰でも登録でき、即公開 |
| 旅行者のログイン | 閲覧は不要。チャットか予約を始めるときに登録 |
| 地元らしさ | 点数は付けない。客層・営業年数・主要駅からの所要時間を載せ、旅行者が判断 |
| 絞り込み | カテゴリ、エリア、予算、客層、営業年数、主要駅からの所要時間 |
| 予約の確定 | 時間枠ごとの上限人数内なら即時確定。満席なら予約できない |
| 休業の扱い | 定休日（曜日）と受付停止日（日・期間） |
| 受付締切 | 事業者が選ぶ（当日OK／前日まで／2日前まで） |
| キャンセル（旅行者） | 事業者ごとに設定。当日キャンセル料を取らない設定もできる |
| キャンセル（事業者） | 理由を選んでキャンセルできる。旅行者に翻訳して通知 |
| 支払い | 体験代金は現地払い。カードは登録のみで、無断キャンセルの抑止に使う |
| 問い合わせ | 予約前でも予約後でも翻訳チャットで質問できる |
| 翻訳 | AI翻訳。掲載文とチャットを英語・簡体字に |
| 料金表示 | 日本円を正とし、選んだ通貨の目安を併記。レートの取得日時を表示 |
| キャラクター | 一覧画面で一言話すだけ |
| 通知 | メールのみ（旅行者・事業者とも） |

### カテゴリ別項目

| カテゴリ | 予約の単位 | 特有の項目 |
| --- | --- | --- |
| 体験 | 時間枠×人数 | 持ち物、最少催行人数 |
| 飲食店 | 時間枠×人数 | 食事制限への対応（ベジ・ハラール・アレルギーなど）、コース／アラカルト |
| ツアー | 時間枠×人数 | 集合場所、行程、ガイドの言語 |

### 予約のステータス

確定 → 来店済み／来店なし／旅行者キャンセル／事業者キャンセル

### キャンセルポリシーの設定【提案】

| 設定 | 選択肢 |
| --- | --- |
| 無料キャンセルの期限 | 当日まで／前日まで／3日前まで |
| 期限後のキャンセル料 | なし／あり（金額を入力） |

キャンセル料は自動では請求しない。事業者が「来店なし」や期限後のキャンセルを記録し、運営が判断して登録カードに請求する。

### 為替の目安表示【提案】

- 対応通貨：SGD、USD、CNY、HKD、TWD、KRW、EUR
- レートは1日1回取得し、「目安・○月○日時点」と表示する。

### MVPの対象外（次フェーズ）

- 承認型の予約リクエスト、上限を超える予約の相談フロー
- おすすめ順と理由の表示（ルールベース → AI）
- キャラクターの会話型の初回登録、各画面での一言、よくある質問
- 地図表示、現在地からの検索
- 保存リスト
- 前日リマインド、はじめてガイド、日本語カード
- 手数料の決済、全額事前決済
- プッシュ通知、SMS、LINE通知
- 用語集、「翻訳がおかしい」ボタン
- 運営の管理画面（MVPはDBを直接操作）
- 掲載前の審査・電話確認
- レビュー、来店後アンケート、入店支援、宿の予約

### 要確認事項

- [ ] 即公開による架空の掲載や誇張への対策（報告ボタンだけで足りるか）
- [ ] キャンセル料を請求するときの運用（誰が判断し、どう連絡するか）と、そのための利用規約
- [ ] カード登録の決済代行サービス（Stripeなど）
- [ ] エリアの一覧（初期は宇治・京都市内など、選択式にするか）
- [ ] 主要駅の決め方（事業者が自由に入力するか、駅の一覧から選ぶか）
- [ ] ツアーの掲載条件（旅行業法上の登録が関わる可能性がある）
- [ ] キャラクターのデザイン、名前、一覧画面での一言の内容
- [ ] 成功指標（KPI）。候補は、登録店舗数、一覧→詳細→予約の転換率、チャットから予約に進んだ割合、無断キャンセル率

### リスク

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 掲載店が少ない | 絞り込むと何も出ない | 初期は地域を絞り、運営が事業者に登録を働きかける |
| 即公開による架空・誇張の掲載 | 旅行者の信頼を失う | 報告ボタン、運営による非公開化。必要なら審査制へ移行 |
| 事業者が予約に気づかない | 当日行っても受け入れてもらえない | 確定時のメール通知、受付締切の設定。次フェーズでプッシュ・LINE通知 |
| 即時確定による受け入れ不可 | 臨時休業などで当日トラブルになる | 受付停止日の設定、事業者キャンセルと翻訳した理由の通知 |
| 無断キャンセル | 事業者が離脱する | カード登録、キャンセルポリシーの明示 |
| 誤訳 | 食事制限などでトラブルになる | AI翻訳、原文表示。次フェーズで用語集とエラー報告 |
